# 의미 있는 페이지 구성

- 시맨틱 HTML의 의미와 필요성
- 소개 영역과 주요 탐색: `header`, `nav`
- 핵심 콘텐츠: `main`
- 주제별 영역과 독립적인 콘텐츠: `section`, `article`
- 보충 정보와 마무리 정보: `aside`, `footer`
- `div`·`span`과의 차이
- 기존 소개 페이지를 의미 있는 영역으로 재구성

## 1. 시맨틱 HTML

### 내용의 역할을 태그로 표현하기

시맨틱(semantic)은 의미와 관련된 말이다. **시맨틱 HTML**은 내용의 역할에 맞는 요소를 선택하여 문서의 구조와 의미를 표현하는 방식이다.

앞에서 배운 `h1`, `p`, `ul`, `a`도 각각 제목, 문단, 목록, 링크라는 의미를 가진다. 이번에는 이러한 내용을 페이지의 역할별 영역으로 묶는 요소를 배운다.

```html
<div>홍길동의 학습 기록</div>
<div>오늘은 HTML의 문서 구조를 배웠습니다.</div>
```

위 내용을 다음처럼 작성하면 제목과 문단의 역할을 알 수 있다.

```html
<h1>홍길동의 학습 기록</h1>
<p>오늘은 HTML의 문서 구조를 배웠습니다.</p>
```

페이지의 큰 영역도 같은 원리로 구성한다.

| 요소 | 역할 |
| --- | --- |
| `header` | 페이지나 해당 영역의 소개·탐색에 도움이 되는 내용 |
| `nav` | 주요 탐색 링크를 모은 영역 |
| `main` | 페이지의 핵심 콘텐츠 |
| `section` | 하나의 주제로 묶은 영역 |
| `article` | 독립적으로 다룰 수 있는 완결된 콘텐츠 |
| `aside` | 주변 콘텐츠와 간접적으로 관련된 보충 정보 |
| `footer` | 페이지나 해당 영역의 작성자·저작권 등 마무리 정보 |

### 의미와 화면 배치 구분하기

- `header`를 쓴다고 화면 위쪽에 고정되지 않는다.
- `aside`를 쓴다고 오른쪽에 배치되지 않는다.
- `footer`를 쓴다고 브라우저 화면 맨 아래에 붙지 않는다.
- 이 요소들은 보통 기본 스타일에서 블록 방식으로 표시된다. 구체적인 위치, 색상, 크기는 CSS로 정한다.

의미 있는 구조는 코드를 읽는 사람과 문서를 처리하는 도구에 도움이 된다. 화면 낭독기에서도 주요 영역이나 제목을 이용한 탐색에 활용할 수 있다. 다만 태그만 바꾼다고 접근성 문제가 모두 해결되거나 검색 순위가 보장되는 것은 아니다.

## 2. 소개 영역: `header`

`header`는 페이지나 해당 영역의 소개·탐색을 돕는 내용을 묶는다. 사이트 이름, 페이지 제목, 소개 문장 등을 넣을 수 있다.

### 페이지의 소개 정보 작성하기

1. `lab05/exam01.html`을 생성하고 Emmet의 `!`로 기본 구조를 작성한다.
2. 문서 언어를 `ko`, 문서 제목을 `홍길동의 학습 기록`으로 수정한다.
3. `body` 안에 다음 예제를 작성한다.

```html
<header>
  <h1>홍길동의 학습 기록</h1>
  <p>HTML을 배우며 만든 결과를 소개합니다.</p>
</header>
```

- `header`와 `head`는 서로 다르다.
- `head`는 문서 제목, 문자 인코딩 등의 메타데이터를 담는다.
- `header`는 일반적으로 `body` 안에서 사용자에게 보이는 소개 내용을 담는다.
- 페이지 전체의 `header` 외에도 `article` 안에서 해당 글의 제목과 작성 정보를 묶는 `header`를 사용할 수 있다.
- 모든 영역에 반드시 `header`를 넣을 필요는 없다.

## 3. 주요 탐색 영역: `nav`

`nav`는 사이트의 주요 메뉴나 페이지의 목차처럼 중요한 탐색 링크를 모은 영역이다. 앞 단원에서 배운 목록과 하이퍼링크를 함께 사용할 수 있다.

### 메뉴를 의미 있게 묶기

1. `exam01.html`의 `header` 안에서 소개 문장 다음에 `nav`를 추가한다.
2. 세 링크가 앞 단원의 페이지로 이동하는지 확인한다.
3. `Tab`과 `Enter` 키로 메뉴를 이용해 본다.
4. `nav` 안의 `ul`을 그대로 유지하여 영역과 목록의 역할을 구분한다.

```html
<nav aria-label="주요 메뉴">
  <ul>
    <li><a href="../lab03/index.html">소개</a></li>
    <li><a href="../lab03/schedule.html">학습 시간표</a></li>
    <li><a href="../lab03/contact.html">문의 안내</a></li>
  </ul>
</nav>
```

- `nav`는 탐색 영역, `ul`은 메뉴 목록, `a`는 실제 이동 링크를 나타낸다.
- `nav`를 쓰는 것만으로 링크가 생성되는 것은 아니다.
- 모든 링크를 `nav`로 감쌀 필요는 없다. 본문 중 참고 문서 링크 하나는 보통 `p` 안에 작성하면 된다.
- 한 페이지에 주요 메뉴와 본문 목차처럼 여러 `nav`가 있을 수 있다.
- `aria-label`은 보조 기술에서 영역을 구분할 수 있는 이름을 제공한다. 화면에 제목으로 표시되지는 않는다.

위 상대 경로는 현재 문서가 `lab05` 안에 있고, `lab03`의 종합 실습 파일들이 작성되어 있다는 가정이다.

## 4. 핵심 콘텐츠: `main`

`main`은 해당 페이지의 핵심 콘텐츠를 나타낸다. 여러 페이지에서 반복되는 사이트 메뉴나 저작권 정보와 구분한다.

### 페이지의 중심 내용 묶기

1. `exam01.html`의 `header` 다음에 `main`을 작성한다.
2. `main` 안에 자기소개 제목과 문단을 넣는다.
3. 코드에서 소개·메뉴 영역과 핵심 콘텐츠 영역을 구분해 본다.

```html
<header>
  <h1>홍길동의 학습 기록</h1>
</header>

<main>
  <h2>자기소개</h2>
  <p>웹 개발을 공부하는 홍길동입니다.</p>
</main>
```

- 이번 실습에서는 페이지마다 표시되는 `main`을 하나 작성한다.
- `main`을 `header`, `nav`, `footer`, `aside`, `article` 안에 넣지 않는다.
- 페이지 제목은 위 예제처럼 `header`에 둘 수도 있고, 문서 구성에 따라 `main` 안에 둘 수도 있다.
- `main`은 제목을 대신하지 않는다. 안의 내용을 설명하는 제목도 적절히 작성한다.


## 5. 주제별 영역: `section`

`section`은 하나의 주제로 관련 내용을 묶는 영역이다. 일반적으로 해당 주제를 설명하는 제목을 함께 작성한다.

### 같은 주제의 내용 묶기

1. `lab05/exam02.html`에 기본 구조를 만든다.
2. `body`에 페이지 제목을 담은 `header`와 `main`을 작성한다.
3. `main` 안을 `자기소개`, `관심 분야`, `학습 목표`의 세 `section`으로 나눈다.
4. 각 영역에 `h2`를 작성하고 문단이나 목록을 추가한다.
5. 제목만 읽어도 문서 구성이 이해되는지 확인한다.

```html
<main>
  <section>
    <h2>자기소개</h2>
    <p>웹 개발을 배우고 있는 홍길동입니다.</p>
  </section>

  <section>
    <h2>관심 분야</h2>
    <ul>
      <li>웹 개발</li>
      <li>사진 촬영</li>
    </ul>
  </section>
</main>
```

- `section`은 단순히 테두리나 배경색을 적용하기 위한 상자가 아니다.
- 별도의 주제 없이 스타일을 적용하려고 묶는 경우에는 `div`를 사용할 수 있다.
- `section` 안에서도 하위 주제가 필요하면 다시 `section`으로 나눌 수 있다.
- `section`을 추가한다고 제목 수준이 자동으로 정해지지 않는다. `h2` 아래의 하위 주제에는 `h3`처럼 문서의 계층에 맞게 작성한다.


## 6. 독립적인 콘텐츠: `article`

`article`은 블로그 글, 뉴스 기사, 게시글처럼 독립적으로 다룰 수 있는 완결된 콘텐츠를 나타낸다.

### 하나의 글로 다룰 수 있는 내용

1. `exam02.html`의 `main` 안에 `최근 학습 기록`이라는 `section`을 추가한다.
2. 그 안에 `article` 두 개를 만들고 각각 제목과 학습 후기를 작성한다.
3. 영역 제목은 `h2`, 각 기록의 제목은 `h3`로 작성한다.
4. 각 기록을 따로 읽어도 내용을 이해할 수 있는지 확인한다.

```html
<section>
  <h2>최근 학습 기록</h2>

  <article>
    <header>
      <h3>목록과 링크를 배운 날</h3>
      <p>작성자: 홍길동</p>
    </header>
    <p>관심 분야를 목록으로 만들고 세 페이지를 링크로 연결했습니다.</p>
    <footer>
      <p>분류: HTML 학습</p>
    </footer>
  </article>

  <article>
    <h3>이미지와 미디어를 배운 날</h3>
    <p>소개 사진에 대체 텍스트를 작성하고 영상에 자막을 연결했습니다.</p>
  </article>
</section>
```

### `section`과 `article` 비교하기

| 구분 | `section` | `article` |
| --- | --- | --- |
| 선택 기준 | 같은 주제의 내용을 묶는가? | 하나의 독립된 콘텐츠로 다룰 수 있는가? |
| 예 | 자기소개 페이지의 관심 분야 영역 | 학습 후기 한 편 |
| 포함 관계 | 여러 `article`을 포함할 수 있음 | 글 안에 여러 `section`을 포함할 수 있음 |

글이 길다는 이유만으로 `article`을 선택하지 않는다. 내용의 독립성을 기준으로 판단한다. 반대로 모든 `article`이 반드시 별도 파일이나 URL을 가져야 하는 것은 아니다.

## 7. 보충 정보와 마무리 정보: `aside`, `footer`

### 보충 정보: `aside`

`aside`는 주변 콘텐츠와 간접적으로 관련된 보충 정보를 나타낸다. 관련 자료, 덧붙이는 설명 등을 담을 수 있다.

```html
<aside>
  <h2>함께 읽을 자료</h2>
  <p><a href="../lab04/index.html">이미지와 미디어 실습 결과 보기</a></p>
</aside>
```

- 옆에 배치하고 싶다는 이유만으로 `aside`를 선택하지 않는다.
- 핵심 설명에 꼭 필요한 내용은 단지 짧다는 이유로 `aside`로 분리하지 않는다.
- 글 하나에 관한 보충 정보라면 `article` 안에, 페이지 전체에 관한 보충 정보라면 그에 맞는 위치에 둘 수 있다.

### 마무리 정보: `footer`

`footer`는 페이지나 해당 영역의 작성자, 저작권, 관련 문서 등의 정보를 담는다.

```html
<footer>
  <p><small>&copy; 2026 홍길동. HTML 수업 실습 자료입니다.</small></p>
</footer>
```

- 페이지 전체의 `footer`와 글 하나의 `footer`는 함께 존재할 수 있다.
- `article` 안의 `footer`는 그 글에 관한 정보를 나타낸다.
- `header`와 `footer`는 문맥에 따라 페이지 전체 또는 해당 영역을 설명한다. 화면상의 위치만으로 역할이 정해지는 것은 아니다.

### 실습: 보충 자료와 저작권 추가하기

1. `exam02.html`의 `main` 다음에 보충 자료를 담은 `aside`를 작성한다.
2. 그 다음에 페이지 전체의 `footer`를 추가한다.
3. 관련 자료 링크가 실제 파일로 연결되는지 확인한다.
4. CSS 없이 `aside`가 오른쪽에 자동 배치되지 않는 것을 확인한다.

## 8. `div`·`span`과의 차이

### 목적에 맞는 요소 선택하기

| 내용의 역할 | 사용할 수 있는 요소 |
| --- | --- |
| 페이지의 소개 내용 | `header` |
| 주요 메뉴 | `nav` |
| 페이지 핵심 내용 | `main` |
| 관심 분야라는 하나의 주제 | `section` |
| 학습 후기 한 편 | `article` |
| 부가적인 참고 자료 | `aside` |
| 저작권 안내 | `footer` |
| 의미 없이 여러 요소를 스타일 목적으로 묶음 | `div` |
| 문장 일부를 스타일 목적으로 묶음 | `span` |

### 변경 전과 후 비교하기

```html
<!-- 변경 전 -->
<div class="intro">
  <h1>홍길동의 학습 기록</h1>
</div>
<div class="content">
  <h2>자기소개</h2>
  <p>웹 개발을 배우고 있습니다.</p>
</div>
```

```html
<!-- 변경 후 -->
<header class="intro">
  <h1>홍길동의 학습 기록</h1>
</header>
<main class="content">
  <section>
    <h2>자기소개</h2>
    <p>웹 개발을 배우고 있습니다.</p>
  </section>
</main>
```

`class="content"`라는 이름만으로 브라우저가 핵심 콘텐츠 영역임을 알게 되는 것은 아니다. 역할에 맞는 HTML 요소로 의미를 표현한다.

`div`를 모두 제거할 필요는 없다. 예를 들어 의미 있는 `section` 안에서도 여러 요소에 공통 배경을 적용하기 위해 `div`를 사용할 수 있다.

```html
<section>
  <h2>연락 안내</h2>
  <div style="background: whitesmoke; padding: 12px;">
    <p>담당자: <span style="color: royalblue;">홍길동</span></p>
    <p>수업 시간에 질문해 주세요.</p>
  </div>
</section>
```

## 9. 종합 실습: 소개 페이지 재구성

### 1) 기존 내용 가져오기

1. `lab05/index.html`을 생성한다.
2. `lab03/index.html`의 자기소개, 관심 분야, 학습 목표 내용을 참고하여 가져온다.
3. 아래의 완성 예제처럼 역할별 영역으로 묶는다.
4. 목록과 문단의 의미는 유지하고 제목의 수준을 맞춘다.

파일이 다른 폴더로 이동했으므로 기존 메뉴의 `schedule.html` 같은 경로도 점검한다. 이번에는 앞 단원의 파일을 가리키도록 `../lab03/schedule.html`로 작성한다.

### 2) 완성 예제

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>홍길동의 학습 소개</title>
</head>
<body>
  <header>
    <h1>홍길동의 학습 소개</h1>
    <p>HTML을 배우며 기록하는 나의 성장 과정입니다.</p>
    <nav aria-label="주요 메뉴">
      <ul>
        <li><a href="index.html">소개</a></li>
        <li><a href="../lab03/schedule.html">학습 시간표</a></li>
        <li><a href="../lab03/contact.html">문의 안내</a></li>
      </ul>
    </nav>
  </header>

  <main id="content">
    <section id="intro">
      <h2>자기소개</h2>
      <p>안녕하세요. 웹 개발을 공부하는 홍길동입니다.</p>
    </section>

    <section id="interests">
      <h2>관심 분야</h2>
      <ul>
        <li>웹 개발</li>
        <li>사진 촬영</li>
      </ul>
    </section>

    <section id="goals">
      <h2>학습 목표</h2>
      <ol>
        <li>내용의 의미에 맞는 HTML 요소를 선택한다.</li>
        <li>여러 페이지를 하이퍼링크로 연결한다.</li>
        <li>브라우저에서 결과를 확인한다.</li>
      </ol>
    </section>

    <section id="records">
      <h2>최근 학습 기록</h2>
      <article>
        <h3>목록과 링크 실습</h3>
        <p>관심 분야를 목록으로 만들고 소개·시간표·문의 페이지를 연결했습니다.</p>
        <footer>
          <p>작성자: 홍길동</p>
        </footer>
      </article>
      <article>
        <h3>이미지와 미디어 실습</h3>
        <p>이미지에 대체 텍스트를 작성하고 동영상에 자막을 추가했습니다.</p>
      </article>
    </section>
  </main>

  <aside>
    <h2>함께 읽을 자료</h2>
    <p><a href="../lab04/index.html">이미지와 미디어 실습 결과</a></p>
  </aside>

  <footer>
    <p><small>&copy; 2026 홍길동. HTML 수업 실습 자료입니다.</small></p>
    <p><a href="#content">본문 시작으로 이동</a></p>
  </footer>
</body>
</html>
```

### 3) 문서 구조 읽기

```text
body
├── header
│   ├── h1: 홍길동의 학습 소개
│   ├── p: 소개 문장
│   └── nav: 주요 메뉴
├── main
│   ├── section: 자기소개
│   ├── section: 관심 분야
│   ├── section: 학습 목표
│   └── section: 최근 학습 기록
│       ├── article: 목록과 링크 실습
│       │   └── footer: 해당 글의 작성자 정보
│       └── article: 이미지와 미디어 실습
├── aside: 함께 읽을 자료
└── footer: 페이지 전체의 마무리 정보
```

위 그림은 주요 요소를 중심으로 정리한 포함 관계이다. 페이지 전체의 `footer`와 `article` 내부의 `footer`가 서로 다른 범위의 정보를 제공하는지 확인한다.

### 4) 페이지 목차 추가하기

페이지 제목 아래의 사이트 메뉴와 별도로, `main`의 맨 앞에 다음 목차를 추가할 수 있다.

```html
<nav aria-label="본문 목차">
  <ul>
    <li><a href="#intro">자기소개</a></li>
    <li><a href="#interests">관심 분야</a></li>
    <li><a href="#goals">학습 목표</a></li>
    <li><a href="#records">최근 학습 기록</a></li>
  </ul>
</nav>
```

`주요 메뉴`는 페이지 사이를, `본문 목차`는 현재 페이지의 주제 사이를 이동한다. 서로 다른 이름을 지정하면 보조 기술에서 탐색 영역을 구분하는 데 도움이 된다.

### 5) 동작과 구조 점검하기

- 표시되는 `main`이 하나인지 확인한다.
- `section`마다 주제를 설명하는 제목이 있는지 확인한다.
- `h1` → `h2` → `h3`가 내용의 계층과 일치하는지 확인한다.
- 각 `article`을 따로 읽어도 하나의 학습 기록으로 이해할 수 있는지 확인한다.
- `aside`가 핵심 본문이 아닌 보충 정보인지 확인한다.
- 주요 메뉴와 목차 링크가 동작하는지 확인한다. 문서가 짧으면 내부 이동 시 화면 변화가 작을 수 있다.
- 개발자 도구의 Elements(요소)에서 실제 중첩 구조를 확인한다.
- CSS를 추가하지 않아 화면이 크게 바뀌지 않아도, HTML이 전달하는 역할은 어떻게 달라졌는지 설명한다.
